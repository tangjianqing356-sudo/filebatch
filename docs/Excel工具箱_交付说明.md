# Excel 工具箱 —— 交付说明

> 本轮改动尚未推远程、未发版本。
> 下一步是 Windows 真机 / CI 验证，本文最后一节列了要重点看的点。

## 一、做成了什么

左边导航原来的「Excel / CSV 合并」换成了「**Excel 工具箱**」，点进去是六个标签页：

| 标签 | 功能 | 输出 |
|---|---|---|
| 合并 | 原有功能，逻辑一行没动 | 单个文件 |
| 去重 | 按选定列找重复，留第一条 / 最后一条 | 新目录，`原名_去重.xlsx` |
| 两表对比 | 明确选出 A 表和 B 表来比 | 单个文件，4 张工作表 |
| 数据清洗 | 删空行、去空格、去换行 | 新目录，`原名_清洗.xlsx` |
| 批量拆表 | 按某列的值拆成多个文件 | 新目录，`原名_值.xlsx` |
| 格式统一 | 表头 / 对齐 / 边框 / 列宽 / 数字格式；字体默认不改 | 新目录，`原名_格式化` + 源扩展名 |

每个标签页都是**独立的一套** BaseJobPage：自己的文件清单、参数、预览、执行线程、日志。
走的还是统一的 `参数 → plan → 预览 → 用户确认 → execute → result/log`，没有任何一条绕过。

界面截图见 `docs/screenshots/09a` ～ `09f`，六个标签页各一张，都是当前版本重新生成的。

## 二、架构是怎么摆的

按要求**没有**往 `table_job.py` 里继续堆。

```
core/excel/
  workbook.py     读写与格式识别（所有功能共用的底座）
  runner.py       统一的执行循环：取消检查、跳过处理、逐项异常隔离、进度回调
  inspect.py      看表头、行数、表头一致性体检、"有没有我们保不住的东西"
  merge_job.py    合并（从 table_job.py 搬过来的）
  dedupe_job.py   去重
  compare_job.py  两表对比
  clean_job.py    数据清洗
  split_job.py    批量拆表
  format_job.py   格式统一

ui/excel_toolbox/
  toolbox_page.py  容器：六个标签页，懒加载，把收尾接口转发给子页面
  columns.py       后台读表头的线程 + 选列控件 + ColumnAwarePage 基类
  dedupe_page.py / compare_page.py / clean_page.py / split_page.py / format_page.py
```

**界面里没有一行 openpyxl 业务逻辑**，全部在 core 层。界面只做三件事：收参数、调 plan/execute、展示。

`core/table_job.py` 保留成一个显式 re-export 的兼容层，所以原有的合并测试和
`ui/pages/table_page.py` 一个字都不用改。

## 三、这一轮按你拍板的四条做的改动

### 1. 预览阶段对**全部**选中文件做后台表头体检

问题背景：列下拉只读前 20 个文件（读全部在几百个文件时会明显卡），
用户完全可能选到一个"只有前面几个文件才有"的列。

现在的做法：

- 点「生成预览」时，先在**后台线程**里把全部目标文件的表头读一遍，
  主线程只负责转进度，弹一个可取消的「正在检查 N 个文件的表头」进度框
  （文件少时 400ms 内完成就不弹，不闪屏）
- 结果按三类摆出来，全部写进执行日志，**执行前**就能看到：
  - **读不了的**（旧 .xls、加密、损坏）→ 跳过
  - **缺必需列的** → 跳过，日志里逐个点名"缺少「手机」"
  - **表头和基准不一致但必需列都在** → 照常处理，预览表对应行加 `⚠ 表头和其它文件不一致`
- 缺列的文件在预览表里就是一条**带原因的跳过项**，不会等到 execute 才失败
- 体检结果按 (文件清单 + 必需列 + 是否有表头) 缓存；三者任一变了自动作废重算

判断逻辑在 `core/excel/inspect.check_headers()`，纯 Python 不依赖 Qt，单独有 14 个测试。

一条端到端验收专门盯这个场景：20 个正常文件 + 1 个缺列的，
断言体检覆盖了 21 个文件、缺列那个被点名、它不产出结果文件。

### 2. 两表对比不再靠清单顺序猜 A/B

加了两个明确的「A 表」「B 表」下拉，外加一个「交换 A / B」按钮。
清单里可以放一堆文件，挑其中两个来比（以前必须正好放 2 个）。

边界情况都处理了，每条都有测试：

| 情况 | 行为 |
|---|---|
| 刚加完文件 | A = 第 1 个，B = 第 2 个 |
| 把 A 选成 B 当前的文件 | B 自动让到另一个文件，两边永远不同 |
| 清单里只有 1 个文件 | B 留空，界面写明"至少放 2 个"，预览被拦住 |
| 删掉正在用的文件 | 两个下拉重建，选中的自动落到还在的文件上 |
| 清空清单 | 两个下拉一起清空，不留悬空路径 |
| 换了 A 或 B | 列下拉按新的两个文件重读，表头体检也重来 |

对比的列名和表头体检**只看 A、B 两个文件**，清单里其它文件不参与。

### 3. 格式统一：字体、字号、对齐默认都「保留原设置」

上一轮字体默认固定微软雅黑，方向是错的；这一轮把对齐也按同一套规矩补齐了。
现在四个样式项的约定完全一致：

| 参数 | 默认 | 核心层表示 |
|---|---|---|
| 字体 | 保留原字体（不修改） | `font_name: str \| None = None` |
| 字号 | 保留原字号（不修改） | `font_size: int \| None = None` |
| 正文对齐 | 保留原对齐（不修改） | `body_align: str \| None = None` |
| 表头对齐 | 保留原对齐（不修改） | `header_align: str \| None = None` |

- `None` 明确表示"不改"，不是"用某个默认值"
- 四项**互相独立**：只选字体不选字号、只改表头对齐不动正文，都可以
- 表头对齐和正文对齐是两个独立下拉，没有绑死
- 仍然不按 Windows / macOS 自动切换任何东西

实现上的关键点是两个同构的辅助函数：

- `merged_font()`：在单元格**原来的** Font 上只改用户指定的那几项
- `merged_alignment()`：只改 `horizontal` 一项，
  `vertical` / `wrap_text` / `indent` 全部沿用原值

两个函数在"没有需要改的东西"时都返回 `None`，调用方就不去给这个单元格赋值。

**关于「保留」的准确含义**：指的是**不修改该单元格对应的那个属性**。
不是文件字节级不变——用 openpyxl 打开再保存，
xlsx 内部的 XML 结构和压缩方式会重新生成，这一点没法也不该承诺。

**这条要能成立，必须先改掉写文件的方式**，见下一节。

### 3b. 为了保住字体，必须停止"重建工作簿"——顺带修好了两个数据丢失

原来的 `_apply_format` 是**读出值另建一个新工作簿**。那样做的话，
不管参数写什么，原字体都一定没了。查的时候发现它还顺手毁掉两样东西：

| 问题 | 原来 | 现在 |
|---|---|---|
| 原字体 | 一律被覆盖 | 默认完整保留 |
| **多个工作表** | 只剩一个，名叫"格式化结果" | 原样保留，每个表都刷到 |
| **数字类型** | `100` 变成文本 `'100'` | 仍然是 `int` / `float` / 日期 |

现在改成**打开原工作簿、在上面刷样式、另存为新文件**。
原文件本身不做任何修改（只读打开、另存到新路径）。

后两条是我在改字体时顺手发现的，不是你提的——但它们和字体是同一个根因，
不一起修的话字体也保不住。都补了回归测试。

### 3c. 能力边界的说法也跟着改了（原来的警告是错的，但也不能反过来打包票）

不重建工作簿之后，我拿验收样例实测了一轮打开→保存：

| 内容 | 验收样例的结果 | 提示档位 |
|---|---|---|
| 图表 | 可保留 | ℹ 需留意 |
| 图片 | 可保留 | ℹ 需留意 |
| 条件格式 | 可保留 | ℹ 需留意 |
| 表格对象 | 可保留 | ℹ 需留意 |
| 宏（VBA） | 可保留——`.xlsm` 用 `keep_vba=True`，输出扩展名跟随源文件 | — |
| 数据透视表 | 很可能保不住，openpyxl 支持不完整 | ⚠ 高风险 |

**措辞上刻意避开两个方向的过度承诺：**

- 不说"你的图表会丢"——会把用户吓得不敢用一个多半能用的功能
- 也不说"一定保留"——Excel 的对象模型很大，
  上面那一行的准确意思是"**当前验收样例已验证可保留，复杂 Excel 对象仍可能存在兼容性差异**"

所以预览提示是两档：
- ⚠ `{数据透视表} 很可能保不住，openpyxl 对它的支持不完整。请先备份原文件。`
- ℹ `{图表、图片…}：验收样例已验证可保留，复杂对象仍可能有兼容性差异，建议执行后核对`

**继续按风险对待、不做任何保证的**：数据透视表、切片器、
ActiveX / 窗体控件、外部链接、复杂宏工作簿。

有测试专门盯着这两段提示里不出现"一定""保证"这类字眼，
也盯着实现别哪天退回重建工作簿。

## 七、跨平台文件名 / 路径

拆表功能会拿**用户数据里的列值**当文件名和工作表名，这是整个工具箱里最容易在换台机器时炸掉的地方。
处理方式：统一按 Windows 那套最严的规则生成，两个平台拆出来的名字保持一致。

1. **`core/naming.py` 加了 Windows 保留设备名处理** ——
   `CON` / `NUL` / `PRN` / `AUX` / `COM1-9` / `LPT1-9` 在 Windows 上做文件名会被系统直接拒绝。
   平时碰不到，但列值是用户数据，完全可能出现。现在会变成 `CON_`，保留可读性。
2. **`split_job.make_filename` 按字符数和字节数双重截断** ——
   原来只截 120 个字符。120 个中文按 UTF-8 是 360 字节，
   超过 Linux / 很多网络共享的 255 字节单文件名上限。现在两道都过，且不会把多字节字符切成半个。

其余已覆盖：非法字符 `\ / : * ? " < > |`、结尾的点和空格、整串都是非法字符的兜底、
清洗后撞名的自动避让、中文 / 空格 / emoji 列值、输出目录不存在时自动创建。
工作表名单独一套（Excel 的非法字符集和 31 字上限不一样），在 `workbook.safe_sheet_name` 里统一兜底。

## 八、能力边界（都是明确提示，不静默处理）

- 支持 `.xlsx` / `.xlsm` / `.csv` / `.tsv`
- **旧版 `.xls`**：靠魔数识别（OLE2 容器），预览里提示"请先用 Excel 另存为 .xlsx"
- **加密的 xlsx**：外层同样是 OLE2，会被识别出来并提示是密码问题或改过扩展名
- **`.xlsb`**：单独提示
- **数据清洗不做任何数据类型转换**：身份证号、`001`、`3-5`、`1.20`、全角数字一律原样保留。
  这条有专门的测试锁着（`test_不做类型转换`）
- **格式统一只改用户明确要求改的东西**。字体 / 字号默认「保留原样」，
  挑了具体字体才会改；也不按平台自动切换
- **格式统一在原文件的副本上改样式**，所以图表、图片、条件格式、表格对象、宏、
  多个工作表都保留，数字也不会变成文本。只有**数据透视表**可能保不住，
  预览里会单独标出来。只提示，不阻止——要不要继续由用户决定
- **格式统一只收 `.xlsx` / `.xlsm`**，CSV 没有格式可设，会在预览里说明
- **拆表数量上限**：默认 200，硬上限 2000。超了会拦下来并提示"多半是选错了列"

## 十、剩余风险 / 下一步

### 1. Windows 真机与 CI 尚未验证（**仍然是最大的未知**）

到目前为止全部验证都在 macOS 上完成。Windows 相关的保护是
**按规则写死 + 单元测试 + macOS 上的对照运行**，
不是在真 Windows 上跑出来的。两个跨平台 skip 的测试在 Mac 上不会执行。

第十一节把真机验收压缩成了四条命令，清单见 `docs/Windows验收清单.md`。

Windows 侧要重点确认的：

- **Excel 工具箱六个功能**各走一遍完整流程
- **中文路径**（用户名带中文、路径带空格）
- **长文件名**：按一个值很长的列拆表，看 260 字符限制和长路径探测的实际表现
- **保留名**：列值含 `CON` / `NUL` / `COM1` 时能不能正常落盘
- **文件占用**：源文件正在 Excel 里打开时执行，错误提示是否是人话
- **PyInstaller 冻结环境**：Windows 上重跑 `--selftest` / `--acceptance`

### 2. 大文件全部读进内存

`read_table` 一次性把整张表读进 list。`MAX_ROWS` 限 100 万行，
但 100 万行 × 20 列的字符串在内存里是几个 G。目前没有流式处理，也没有内存保护。
普通用户的表基本到不了这个量级，但如果预期会有很大的表，这是要单独做的一件事。

### 3. 表头体检会让"文件很多"时的预览变慢

全量体检要把每个文件都打开读一遍。几百个文件时这一步会有明显等待
（有可取消的进度框，不会假死）。这是为了"缺列必须在执行前暴露"付的代价，
是本轮明确选的取舍。如果以后觉得慢，可以考虑只读表头行而不读全表——
现在用的 `inspect_file` 会顺带统计行数，那部分是可以省掉的。

### 4. 格式统一的默认值现在很"保守"

字体、字号、正文对齐、表头对齐默认都不改之后，
默认参数下「格式统一」实际做的只剩：
**表头加粗加底色、冻结表头、加边框、列宽自适应**。
字体和对齐要用户自己去选。这是你定的方向，只是提醒一下默认行为的范围。

还在无条件应用的只有：边框、列宽、表头加粗/底色、冻结表头——
这几项都有独立的开关可以关掉，所以不需要额外的"保留原样"选项。

### 5. 列下拉仍然只读前 20 个文件

`MAX_INSPECT_FILES = 20`。这只影响"下拉里能选到哪些列"，
不影响正确性——预览阶段的全量体检会把所有问题文件摆出来。
如果第 21 个文件有一个前 20 个都没有的列，用户在下拉里选不到它。
真要选，目前得先把那个文件排到前面。

## 十一、Windows 验收准备（本轮新增）

格式统一封板后进入 Windows 阶段。**Windows 真机和 CI 我都跑不了**——
这台是 macOS，CI 需要推远程而你要求先不推。
所以这一轮做的是"把真机验收压缩成几条命令"，外加修掉准备过程中发现的真实问题。

### 1. 新增 `--platform-check`：一条命令覆盖平台边界

`--selftest` 管依赖完整性，`--acceptance` 管功能走得通，
新增的 `--platform-check` 管**操作系统的脾气**，共 11 项：

| 检查 | 覆盖清单第几项 |
|---|---|
| 中文与空格路径 / emoji 路径 | 5 |
| 长路径读写（贴着实测上限跑） | 5 |
| 超限路径在**预览阶段**被拦下 | 5 |
| 源文件被占用 | 6 |
| 输出目录没有写权限 | 6 |
| 输出目录 = 源目录 | 6 |
| 输出位置不存在（盘符没了 / 网络盘断了） | 6 |
| `.xlsm` 往返（扩展名不变、数字类型不变） | 7 |
| 格式统一默认不改字体/字号/对齐、多表不丢、数字不变 | 8 |
| 真实宏文件的宏保留（需 `--xlsm <文件>`） | 8 |

每一项都会标注它在当前平台**算不算真结论**——
文件占用、权限、盘符这几条在 Mac 上只能证明代码不崩，
Windows 的文件锁和权限模型完全是另一回事。

### 2. 修掉一个真实问题：错误信息里漏出 errno

准备过程中 `--platform-check` 立刻抓到一条：输出位置不存在时，
用户看到的是

```
系统错误：[Errno 30] Read-only file system: '/没有这个挂载点'
```

Windows 上会是 `[WinError 3] 系统找不到指定的路径。`。
普通用户既看不懂也不知道下一步该干嘛。

这个写法 `f"系统错误：{e}"` **六个功能的执行循环里都有**，不是 Excel 独有的。
已统一改成 `core/oserrors.describe()`：

- 按 errno 常量给中文说明（磁盘满 / 路径太长 / 只读 / 没权限 / 位置不存在 /
  设备断开 / 跨磁盘移动…），绝不拼原始异常
- 界面层的 `humanize()` 也委托同一份，避免弹窗和日志两套措辞
- 18 条测试盯着，含一条防回归：六个 job 的源码里再出现
  `系统错误：{e}` 就直接失败

这是**修真实问题**，不是扩需求——格式统一没有动。

### 3. 冻结产物的验收补强

`--acceptance` 的"格式统一"样例原来只有普通表格，
现在换成一张**图表 + 图片 + 条件格式 + 表格对象**都有的工作簿。
交付说明第八节写的"验收样例已验证可保留"，指的就是这个样例——
必须在**冻结产物**里核对，不能只在 pytest 里过。

### 4. CI 工作流

- Windows job 和 macOS job 都加了 `--platform-check` 步骤
- 修掉一处过时的步骤名（"6 个功能" → 11 个功能）
- 其余（打包、版本信息与图标校验、Defender 检查、DPI 截图、artifact）保持原样

### 5. 真机清单

`docs/Windows验收清单.md`：四条命令 + 一份肉眼核对表 + 最终报告的填空模板。
覆盖你列的 10 项，每一项标明是自动检查还是要人眼看。

### 6. 这一轮唯一验不了的

**带宏的真 `.xlsm`**。没法凭空造一个合法的 `vbaProject.bin`
（那是 OLE2 复合文档，伪造出来的不可信）。
所以 `--platform-check --xlsm <你的文件>` 留了个口子，
在真机上拿一个真的带宏文件跑一次就有结论了。
代码里 `.xlsm` 走 `keep_vba=True`、输出扩展名跟随源文件，
往返测试已通过，但**宏本身是否保住只能靠真文件验证**。
